## Key Code Changes

- Default plans now resolve to 23 skills and 23 commands for command-capable adapters.
- Letta Code still receives skills only, so its default plan resolves to 23 skills and zero commands.
- Explicit `plan frontend-design uncodixify` still resolves both skills and both paired commands.
- `gaps --json` remains `ok: true` but reports the intentional omissions as warnings because the current inventory checker treats every non-default packaged skill as a default-bundle gap.
- No installer or update algorithm was changed; this is a manifest-level default selection change.

## Architecture Decisions

- Keep source assets and wrappers intact. Removing default membership is not deleting a capability.
- Treat design direction and post-render cleanup as opt-in workflows rather than ambient default context.
- Preserve the existing receipt model. Existing installations should not be silently mutated by a packaging metadata edit.
- Make the new policy discoverable in README and the compact LLM index instead of relying on the manifest alone.

## Honest Feedback

1. **รอบแรกผมควรเพิ่ม test เชิงนโยบายให้ครบตั้งแต่ต้น** — การเปลี่ยน default membership ต้องมีทั้ง negative assertion และ explicit-install regression proof; ผมมีอย่างหลังจาก test เดิมกระจายอยู่ แต่ไม่ได้ตั้งใจอ่านเป็น contract เดียวตั้งแต่แรก จึงเหลือ assertion เก่าหลุดมาและต้อง rerun เต็มชุดอีกครั้ง
2. **`gaps` ใช้คำว่า omission เหมือนเป็น defect ทั้งที่ตอนนี้เป็น policy ที่ตั้งใจ** — ตอนนี้ระบบยังรายงาน warning สำหรับ `frontend-design` และ `uncodixify` ซึ่งไม่ทำให้ command fail แต่ทำให้สัญญาณ inventory noisy ขึ้น หาก default bundle จะมี opt-in skill เพิ่มอีก ควรมี metadata สำหรับ intentional opt-out หรือแยก warning class ในงานถัดไป ไม่ควรแก้เงียบๆ ในรอบนี้เพราะจะขยาย scope
3. **ต้องไม่ปน source packaging กับ installed-state cleanup** — Global receipts จริงยังมี 25 skills และสอง skill ที่เราถอดออก การบอกว่า “เอาออกแล้ว” โดยไม่แยกสองชั้นจะทำให้ผู้ใช้เข้าใจผิด รอบนี้ผมไม่ได้รัน uninstall/update บน global state ซึ่งถูกต้องตาม scope แต่ final handoff ต้องบอกคำสั่งและผลกระทบให้ชัด

## Lessons Learned

- Manifest membership เป็น source of truth สำหรับ default install; source skill และ paired wrappers ไม่ควรถูกลบเมื่อแค่เปลี่ยน default policy
- `guided --mode update --yes` re-installs receipt-recorded items; มันไม่ prune skills ที่ถูกถอดจาก default bundle
- ทุก default-bundle removal ควรตรวจสามมิติ: future plan/install, explicit opt-in path และ existing receipts
- Inventory gap warnings ต้องแยก intentional opt-out จาก accidental omission เมื่อระบบเริ่มมี optional skill policy จริงจัง
- Full-suite failure หลังแก้ manifest มักเป็น stale positive assertion ใน tests มากกว่าปัญหา resolver; ให้ rerun หลังแก้และรายงาน exact evidence
