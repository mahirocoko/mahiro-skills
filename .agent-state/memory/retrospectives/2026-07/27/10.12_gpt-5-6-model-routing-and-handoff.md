## AI Diary

ผมเริ่มรอบนี้ด้วยความเสี่ยงว่าจะตอบตาม benchmark มากเกินไป ตอนแรกคำว่า Pareto frontier ทำให้สรุปง่ายเกินว่า Luna Max “ดีกว่า” GPT-5.5 แต่พอ Mahiro ถามเลขเทียบตรง ผมต้องกลับไปเปิด chart และพบว่าคะแนน raw ของ Luna Max ต่ำกว่าจริง การแก้คำตอบทันทีเป็นเรื่องถูก แต่ก็น่าจะตรวจ matrix ให้ครบตั้งแต่ก่อนฟันธง รอบนี้เตือนผมอีกครั้งว่าความคุ้มค่า, intelligence, latency และพฤติกรรม agent เป็นคนละแกนกัน

สิ่งที่มีค่าที่สุดไม่ใช่ตารางคะแนน แต่เป็น feedback จาก Mahiro ว่า Luna Max ทำ task ยาวได้ดี การสังเกตนี้อาจสำคัญกว่าคะแนนต่างกันไม่กี่จุด เพราะ pain จริงคือ agent หยุด report ก่อน DoD ผมรู้สึกดีที่เราไม่รีบเปลี่ยน default ถาวร และเลือก pilot 3–5 งานพร้อม metrics แทน อีกอย่างที่ทำได้ดีคือยอมให้ `local-conv-236` เป็น owner เมื่อมันมี context ที่แคบและพร้อมกว่า การรักษา Mahiro Code เป็นตัวตนเดียวไม่ได้แปลว่าทุก conversation ต้องแย่งกันนำ งานนี้ควรพิสูจน์ว่าการแบ่ง execution lane แบบโปร่งใสทำให้ระบบแข็งแรงขึ้นได้จริง

## Honest Feedback

1. **Research เริ่มกว้างเกินจำเป็น** — มีการเปิด subagent research lane ที่ใช้เวลาหลายนาทีแต่ไม่ส่ง partial result ก่อนถูกหยุด แสดงว่า packet ขาด timebox และ partial-handoff contract เราควรให้ Sol ตัดสินจาก evidence ที่เตรียมไว้ ไม่ใช่ปล่อย crawl กว้าง
2. **คำตอบบางช่วงสรุปเกินหลักฐาน** — ผมเคยบอก Luna Max เหมือนเป็น upgrade จาก 5.5 ก่อนตรวจคะแนน effort ต่อ effort และเคยใช้ cost/task เป็นตัวแทน list price จน Mahiroทักว่าความรู้สึกใช้งานจริงแพงกว่า การแก้ภายหลังช่วยได้ แต่กระบวนการที่ดีกว่าคือแยก metric ตั้งแต่ต้น
3. **Conversation telemetry มีข้อจำกัด** — รายงาน local usage ใหญ่มากและมี fork/alias ที่แชร์ history กัน แม้ deduplicate message identity แล้ว conversation totals ยังไม่เท่ากับ independent task samples อีกทั้ง cost เป็น transcript estimate ไม่ใช่ invoice ตัวรายงานระบุ caveat แล้ว แต่การวัด pilot ถัดไปควรเริ่มจาก task-owned record ที่สะอาดกว่า

## Lessons Learned

- Model fit ต้องวัดจาก completion behavior และ rework ไม่ใช่ intelligence benchmark อย่างเดียว
- Cost per benchmark task ไม่เท่ากับ list price หรือ cost ของ persistent large-context agent
- `turn complete` ต้องแยกจาก `goal complete`; final report ควรเกิดเฉพาะ `done`, `blocked` หรือ `needs_human`
- Long-task Luna pilot ต้องเก็บจำนวนคำสั่ง “ทำต่อ”, premature finals, DoD first-pass, rework, context disruption และ verification coverage
- Subagent ทุก lane ต้องระบุ model, deliverable, timebox และ partial handoff อย่าง explicit
- เมื่ออีก conversation มี context และ ownership เหมาะกว่า ควร handoff อย่างโปร่งใสแล้วหยุดแก้ไฟล์ ไม่ควรทำงานคู่ขนานชนกัน
