## Honest Feedback

1. **การใช้คำว่า “พร้อมทั้งหมด” ต้องระวังมากขึ้น** — แม้ workflow source, installed skill และ model default จะพร้อม แต่ current conversation ยังมี Sol override, pilot 3–5 งานยังไม่เกิด และ canonical source ถูก commit โดยอีกจังหวะหนึ่งก่อนคำสั่ง commit รอบท้าย การสรุปต้องแยก runtime ready, longitudinal evidence และ Git state ไม่ให้รวมเป็นคำว่าเสร็จคำเดียว
2. **Custom agent discovery ทำให้เกิดรอบฟื้นตัวที่ไม่จำเป็น** — ผมพยายาม smoke-test `long-task-executor` ใน process เดิมแล้วได้ invalid type เพราะ registry cache ตั้งแต่ startup นี่ไม่ใช่ implementation bug แต่ควรวาง restart boundary ไว้ก่อน test เพื่อประหยัดเวลาและหลีกเลี่ยงสัญญาณลวง
3. **การค้นใต้ `~/.letta/mods` กว้างเกินไปครั้งหนึ่ง** — `rg` ไหลเข้า managed `node_modules` จนได้ผลลัพธ์หลายหมื่นรายการ ก่อนกลับไป canonical repo และ `ccc` การสำรวจครั้งต่อไปควรเริ่มจาก `letta mods list` → package source path → `AGENTS.md` → focused search เท่านั้น

## Lessons Learned

- Evidence validator ต้องปิดทั้ง schema vocabulary และ human provenance; test pass อย่างเดียวไม่ใช่ human acceptance
- Persistent default, conversation override และ explicit subagent model เป็นคนละชั้นและต้อง report แยกกัน
- Custom subagent ควรมีเฉพาะ role/tool/model boundary ที่ต่างจริง; procedure ทั่วไปควรอยู่ใน skill
- Main agent/skills เป็นเจ้าของ model routing และ prompt packet ส่วน mods เป็นเจ้าของ deterministic coordination/evidence state
- Execution Run ควรคง executor-neutral และไม่ spawn, choose model หรือประกาศ Goal complete
- ก่อนสำรวจ installed runtime tree ให้กลับไป canonical repository เพื่อหลีกเลี่ยง generated dependencies และ stale metadata
