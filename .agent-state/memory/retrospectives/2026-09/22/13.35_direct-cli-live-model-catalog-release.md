## AI Diary

The central lesson was uncomfortable but clear: running the right command is
not enough if I inspect only part of its output. I used `sed` to bound a very
large Cursor model catalog and then treated the missing tail as evidence that
Fable 5.1 was unavailable. That was a bad evidence transition. The model was
present later in the same output, and I briefly rewrote the skill toward an
older Fable 5 route. I corrected the source, tests, and installed copy before
release, but the avoidable rework came from optimizing output size before I had
classified the data I needed.

The better pattern emerged during the correction: use exact structured or
anchored extraction for the candidate IDs, and distinguish “not shown in this
slice” from “absent from the complete catalog.” That same discipline exposed a
real stale route in Codex: Spark was named by the skill but absent from the
complete JSON model response. The final diff is therefore smaller and more
truthful than the provisional one—Grok advances to 4.7, Fable 5.1 remains, and
Spark leaves the picker. The session also reinforced the difference between a
binary update and a skill update. Cursor's updater made no binary change; the
useful work was aligning the routing contract and installed skill with live
availability. With a +100% derived weekly session change before this entry, the
important momentum was not raw activity but recovering quickly, preserving the
correct model owner, and turning the mistake into a reusable evidence rule.

## Honest Feedback

1. I misread the conversational context and created a future schedule when
   Mahiro intended immediate execution. The surrounding date question was not
   permission to defer the next independent request. I should have treated the
   newest imperative as the active scope before choosing a scheduling tool.
2. I reported Fable 5.1 as unavailable from a truncated catalog. This was the
   most serious evidence error because it drove an unnecessary source change,
   installation, and correction cycle. Large output should be filtered by exact
   identifiers or parsed structurally, never sampled and promoted into an
   absence claim.
3. I initially summarized “Agent CLI updated” too loosely even though
   `agent update` made no binary change. Future reporting must separate updater
   invocation, observed binary version, canonical skill changes, and installed
   skill refresh so Mahiro can see what materially changed.

## Lessons Learned

- The latest imperative owns scope; a preceding time-conversion question does
  not automatically convert the next request into a scheduled task.
- A partial model-catalog view cannot prove absence. Query exact IDs or parse
  the complete catalog before changing canonical routing.
- CLI binary state, live model availability, curated skill routing, and
  receipt-backed installed copies are four separate facts.
- Curated routing should remove unavailable entries rather than keeping them as
  aspirational choices.
- Tests should assert both the selected current route and the removal of the
  superseded or unavailable route.
