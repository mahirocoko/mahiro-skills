## AI Diary

I learned that the most valuable part of revisiting OMX was not another architecture proposal. It was recognizing how much our existing Direct CLI helper already does. The initial broad receipt idea could have duplicated durable callbacks, recovery, and ownership checks that were already present. Reading the actual target capture and matcher narrowed the work to an optional session identity. I also encountered the same operational weakness while dispatching the fix: the helper accepted the prompt, but the Agy pane was still empty. Inspecting the exact pane rather than trusting a status message let me recover without starting a second writer. That made the distinction between transport acceptance and execution visible, but it did not authorize a broader dispatch rewrite. I kept that adjacent evidence separate. The writer's report and passing tests were useful, yet I still needed to inspect the diff and rerun the focused suite myself. Transferring the changes into main only after Mahiro requested it clarified where the work actually lived. I should continue describing source validation, installed behavior, and live proof separately rather than allowing a successful test suite to imply all three.

## Honest Feedback

Three frictions stood out. First, the reader recovery consumed more time than the narrow finding warranted and failed to write its assigned artifact; the useful finding needed Main's source check before becoming a recommendation. Second, the worktree was not where Mahiro initially looked for changes, so even a technically isolated implementation created discovery overhead. Naming the actual checkout and branch early matters when work is not in the ordinary main tree. Third, provider readiness and callback identity are related but different. The live Agy session had no session ID before its first task, which means strict callback registration can correctly reject an uninitialized target. The release must explain that boundary and preserve explicit watcher fallback rather than claim universal automatic readiness. None of these issues should be hidden behind a green test count or a polished completion summary.

## Lessons Learned

- Preserve existing callback and receipt owners; repair a demonstrated missing invariant instead of introducing a parallel runtime.
- A successful prompt API call is not new execution evidence.
- A model handle does not establish reasoning effort: only the Astra inherited-fork probe verified Low; the earlier fresh-reader timeout cause remains unknown.
- Keep source tests, installed synchronization, and live same-pane replacement proof distinct.
