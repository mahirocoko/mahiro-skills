## AI Diary

I almost treated "remove Pi" as one product surface. The first search made that mistake look cheap: `pi` shows up in the installer, the skill, and the tests, and a careless pass would have deleted the adapter Mahiro still uses to install skills into Pi. The memory note from v0.1.79 already said the lane and the adapter are different contracts, so the right first move was to name that split and stop. Waiting for "เริ่มดำเนินการได้เลย" felt slow for a half-hour task, but it was the difference between a scoped deletion and a broken install target.

The edit itself was mostly subtraction, and subtraction is where I get sloppy. The Pi lane was woven through launch examples, cleanup receipts, and a whole playbook section. When I cut the Pi contract out of `SKILL.md`, the callback heading went with it, and the sentence that says not to infer model catalogs from another executor went too. Tests would have caught the missing sentence. They would not have caught a heading that still left the callback prose readable but unlabeled. I noticed both by rereading the cut, not by trusting the first patch.

The pulse numbers are a poor description of the morning. Thirty-six prior retrospectives, zero today before this note, and a −50% week are file counts. They do not say whether the remaining Cursor, Agy, and Codex lanes are still coherent. The 48 passing tests only prove the assertions I rewrote still match the files. Installed copies of `direct-cli` still contain the old Pi lane until someone updates them. I should not talk about this as finished in a running agent until that refresh happens.

## Honest Feedback

First, the playbook deletion was larger than a careful diff review in one pass. I relied on a second read to restore two non-Pi sentences I had clipped. A smaller sequence, heading check then body check, would have made that miss less likely. Second, this session's Task catalog does not list `git-commit`, so the standing delegation path is unavailable and the commit has to be made here after saying so. That is a real mismatch between the skill and what this CLI session can launch. Third, current memory still contained imperative Pi launch steps after the product decision. Leaving them would have taught the next chat to open a lane the skill no longer has. I marked that block historical, but the long direct-cli memory file is still easy to read as live procedure if a later edit drops the superseding sentence.

## Lessons Learned

- A named CLI lane and the install adapter that shares its name are separate owners. Removing one does not authorize deleting the other.
- When cutting a section out of a skill, reread the neighboring headings and the sentences that were not about the removed topic.
- Current memory that still gives launch steps has to be replaced in the same change, or the next session will revive the lane.
