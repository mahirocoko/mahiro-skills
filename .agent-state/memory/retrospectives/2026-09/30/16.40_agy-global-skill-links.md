## Key Code Changes
`link` creates or records an exact Agy symlink at `~/.gemini/antigravity-cli/skills/<name>` and leaves an unowned Letta link alone. `unlink` and `uninstall` remove only manager-owned Agy links. A foreign symlink at that path still blocks canonical removal. The list legend now includes `l link`, `x unlink`, and `d remove`, and those keys open the existing confirmation for the selected row.

## Architecture Decisions
The canonical copy stays in `~/.agents/skills`. Agy's installer-owned `mh-*` copies stay in `~/.gemini/config/skills/`. External global skills use a third root, the one the live CLI actually scans. `skills.json` in `~/.gemini/config/` was not the live contract for Agy 1.2.14 print mode.

## Honest Feedback
The first friction was trusting the customization guide inside the binary over one live listing. The guide names `skills.json` and `~/` paths. Print-mode `/skills` never mentioned that file and did mention `~/.gemini/antigravity-cli/skills/`. I should have run the listing before choosing a mechanism.

The second friction was describing uninstall as present while the screen Mahiro posted had no remove key. The command and the detail-page `d` were real, and they were invisible from the list. A status line that says "press Enter to see what you can do" is not a shortkey legend.

The third friction was the ownership split already on disk. Some skills are installed by this manager, some are only tracked, and some are not in the receipt at all. `d` can only remove the first group. The new legend makes that key visible, and it still has to say no for External and Tracked rows. That boundary is easy to feel as a missing feature even after the key is printed.

## Lessons Learned
Verify the path a fresh Agy `/skills` listing reports before adding a discovery manifest. Keep list-screen legends aligned with keys that work on that screen.

## Next Steps
