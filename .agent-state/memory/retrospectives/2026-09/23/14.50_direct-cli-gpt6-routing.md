## Honest Feedback

The biggest friction was context separation. The research was good and detailed, but it mixed provider economics, Letta defaults, API behavior, and direct CLI choices. Without an explicit owner map, an agent could easily turn an API benchmark into a CLI picker rule or mistake a local Letta model handle for proof of Codex availability. The second friction was timing: the callback lifecycle test failed once in the full suite and passed immediately when isolated, then the full suite passed on rerun. That is manageable, but it consumes attention during a release flow and makes it important to record the exact failure rather than silently calling the first run green. The third friction was release scope. The direct-cli diff is small and well-tested, but it sits beside prior repository changes and an uncommitted working tree, so commit authorization must remain bound to the exact current diff. The next agent should inspect the staged set carefully, avoid adding unrelated state, and keep release claims separate from the human's later acceptance of any broader workflow changes.

## Lessons Learned

- A model research result should produce a routing hypothesis, not an automatic catalog rewrite.
- For direct-cli, live target-CLI evidence outranks Letta/API metadata.
- A three-tier route is useful: Luna for bounded throughput, Sol High/Max for normal-to-difficult work, Astra for justified flagship escalation.
- Preserve capability-specific exceptions such as imagegen/source-art routes when changing general coding defaults.
