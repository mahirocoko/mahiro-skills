## AI Diary

I liked that this session began with runtime reality rather than an immediate documentation rewrite. The installed commands told me which update mechanism each executor actually owned, and Pi's refusal was useful evidence rather than an obstacle to bypass blindly. Following that ownership led to the isolated package and a clean 0.84.4 update without rewriting its wrapper or provider setup. The model migration itself was small, but it reinforced why the playbook keeps one curated owner instead of copying volatile catalogs into every entrypoint. The most uncomfortable moment was the installed-copy probe: I used `path` as a zsh loop variable, accidentally replaced the shell's executable search array, and then printed PASS even while `rg` emitted command-not-found errors. That was exactly the kind of green-looking evidence I am supposed to distrust. I corrected it openly, rejected the original result, and reran with `set -e`, a non-special variable, and an absolute executable path. The independent verifier then found a more subtle gap: high was asserted directly but xhigh was only covered indirectly. Adding that assertion made the regression match the full migrated contract. With a flat weekly pulse and no earlier retrospective today, this was a compact maintenance session, but it improved both the live runtime and the evidence discipline around it.

## Honest Feedback

Three friction points deserve explicit attention. First, the initial repository discovery used a broad `find .. -name AGENTS.md`, which returned unrelated sibling and dependency paths; starting from the known repo root and reading its root guidance directly would have been faster and quieter. Second, `codex debug models` was captured without first projecting only the fields needed, producing a huge payload containing model instruction templates. The later `jq` projection was the right shape and should have been used from the start. Third, the first installed-copy validator lacked fail-fast semantics and used zsh's special `path` name. That combination allowed command failures to coexist with misleading PASS lines. The correction was sound, but the probe should have been defensively written on its first attempt. The release phase should preserve the good parts of this run: exact live catalog evidence, one canonical owner, negative stale-contract guards, receipt-preserving rollout, and a final independent attempt to disprove the result.

## Lessons Learned

- CLI binary freshness and account/provider model-catalog freshness are separate facts; verify both before changing routing.
- A model-catalog migration should replace the canonical curated owner and every active launch example, then add a negative guard for the superseded family.
- Shell validation is evidence only when command failures terminate the probe; zsh special variables can silently undermine executable lookup.
- Historical model snapshots may retain old slugs when they are clearly non-authoritative and point readers to the current owner.
