## AI Diary

I began with the right architectural instinct—keep durable routing in Direct-CLI and treat Herdr as best-effort transport—but I let the initial design overfit the named-agent API. The first fake suite looked strong, yet the real parent could not receive `agent.prompt` because Letta was visible through metadata rather than registered as a named Herdr agent. The more important failure was behavioral: after intentionally stopping polling, I did not provide a bounded silence deadline, so the experiment looked exactly like a frozen main agent. Mahiro's correction was precise and useful. It forced me to test the topology he actually cared about, not merely the harder-looking cross-space case. Once atomic `pane.run` produced a real turn in the current conversation, the system became concrete rather than theoretical. I also appreciated the repeated verifier pressure. Each round found a race that ordinary happy-path tests missed: transport acceptance preceding acknowledgement, deadline PID persistence, and stale post-dispatch state overwriting a terminal callback. The final deterministic fake transport is better because it reproduces the concurrency window inside `start`, not because it adds another assertion. This session reinforced that event-driven coordination is only trustworthy when silence, retries, receipts, and terminal ownership are explicit. The final live behavior now matches Mahiro's request, but it took more correction loops than it should have.

## What Could Improve

1. Test the user's normal topology first, then expand to cross-space stress cases.
2. A callback design must define its silence deadline before the first live run; “no continuous monitoring” must never mean “wait forever.”
3. Transport capability must be probed against the exact recipient type. A visible Letta pane is not automatically a named Herdr agent.

## Blockers & Resolutions

- **Parent `agent.prompt` failed**: exact error was `agent_not_ready`; resolved with receipt-bound atomic single-line `pane.run`.
- **Main appeared stuck**: resolved with a one-shot sleeping deadline that wakes attention without continuous polling.
- **Accepted delivery was incorrectly terminal**: moved report finalization to exact parent receive acknowledgement.
- **Deadline/start races**: serialized post-dispatch transition and deadline spawn/PID persistence under the job lock; added exact process cleanup and dispatch-race regression.

## Honest Feedback

The largest friction point was that I initially optimized for architectural cleanliness at the expense of the user's observed runtime reality. I treated pane typing as categorically unsafe even though Mahiro had already seen direct cross-tab communication work; the correct move was a narrow, metadata-only, receipt-bound `pane.run`, not an absolute prohibition. Second, the first live experiment lacked a clear wall-clock boundary. Stopping polling was valid, but ending the turn with “waiting” and no automatic attention wake shifted the failure-detection burden back to Mahiro. Third, I trusted an impressive test count too early. The initial tests proved many invariants but did not prove the real parent transport or the concurrency windows around acknowledgement and deadline setup. The corrective process was good—live evidence, exact errors, verifier challenges, deterministic regression—but it was longer than necessary. Future work should begin with one smallest real callback to the exact parent, then add peers, durability, and recovery around that proven transport.

## Lessons Learned

- A Herdr-visible Letta pane is not a named Herdr agent; use exact atomic metadata-only `pane.run` for parent wakes.
- “No continuous monitoring” requires a one-shot silence deadline and durable recovery instruction.
- Accepted transport is not receipt; terminal state belongs to exact receiver acknowledgement.
- Reload and mutate shared job state under one lock after any external transport call.
- Test same-workspace/different-tabs before claiming a cross-tab workflow complete.
