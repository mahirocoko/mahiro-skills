## What transfers

Keep evidence from real conversations, independent per-axis judgments, specific reasons, failed-episode grounding and actionable instruction-owner proposals. Preserve the binary code-quality approve/block decision when actual changes are visible. Take efficiency's human-attention cost and verbosity's recipient perspective seriously rather than reducing them to tool counts or transcript length. Preserve procedure compliance's contextual applicability: only visibly applicable instructions/triggers count.

## What is contextual

Warp's collector supports local storage discovery and inferred project/global skills; this adaptation instead uses explicitly selected Letta identities or Pi session and branch, with bounded supported input and no automatic source discovery. Main's Letta 0.34.8 local native probe found `approval_request_message` for attempted tool calls, piped JSON truncation around 64 KiB and repeated IDs from `--after`. The native adapter therefore captures one `messages list --order asc --limit 500` command directly into private temporary regular files within the approved output parent's workspace, checks growing byte bounds/timeout, and always removes its capture. It makes no pagination or full-history guarantee. Requests remain attempted `tool_request` events with unknown outcome. User wire roles and automation wrapper text are not proof of actual human instructions; provenance remains unverified until evidence review. These are observed transport-specific adaptations, not claims about every Letta backend or future version. No source inference or raw database scans. Warp's local-only scorer claim cannot apply to an API-hosted evaluator: provider transmission needs explicit approval for selected material. The collector does not call a model.

Warp's all-conversations/global-skills scope, A–F curve, weighted overall formula (0.25 efficiency + 0.25 code quality + 0.2 procedure compliance + 0.15 verbosity + 0.15 coverage), coverage heuristics, HTML/share image and marketing CTA are not adopted in approved v1. Their absence is not an assertion that these are universally wrong; they do not serve this bounded causal diagnosis. No replacement weights are invented. Raw rubric numeric scores remain unchanged. Overall metrics, if later approved, cannot prove skill causality.

Upstream Code Quality lists `insufficient_evidence` with weight 0.5 but excludes it from aggregation. The local schema represents abstention as null, including on other axes when evidence is genuinely unavailable. This preserves the source table intact while making missingness explicit instead of manufacturing a neutral observation. Never use null as failure evidence.

Upstream's suggestions-only-from-failed-conversations rule transfers, but a low rubric score is not enough: a recommendation additionally needs an actual missing/wrong instruction, causal evidence, confidence and owner. Ignoring an existing adequate instruction, model variance and product/infra problems are not automatically skill defects. Similarly, absence of a skill-name substring does not prove a trigger-description problem. Preserve counterevidence and allow no-op/abstention.
